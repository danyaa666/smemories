# E05_T-092 — Public photo links: signed token, public-media endpoint, revoke-all (API)

**Epic:** E05-templates-export · **PRD:** [PRD.md](PRD.md) · **Milestone:** M1 · **Risk:** high · **Priority:** P1 · **Type:** feature
**Read first:** `docs/api-contract.md`, `docs/db-conventions.md`, `docs/go-conventions.md`, `docs/media.md`, `docs/redis.md` (limiters), `docs/production-config.md`. Decision **D-32** (README §4).
**Series:** T-092 (this) → T-093 (text export API) → T-094 (web). Do not start T-093/T-094 work here.

#### Description
The owner wants a plain-text export of the book where every photo is a link (D-32, owner answer 2026-10-19: **permanent public links**). A link must open the photo **without a session**, so this task adds the one public way to fetch a book photo, and the owner's control to switch all links of a book off. Photos are third parties' personal data: the design below is the mitigation set the owner accepted with the decision; do not weaken it.

#### Requirements (SHALL)
1. **Link token.** `token = <media public id (ULID)> + "." + base64url(first 16 bytes of HMAC-SHA256(secret, "pm1|" + media_id + "|" + yearbook_id + "|" + link_epoch))`. Pure function in `internal/media` (or a small `internal/medialink` package), no database access, constant-time verify. `secret` is `SMEM_MEDIA_LINK_SECRET` (base64, at least 32 bytes decoded).
2. **Config.** `SMEM_MEDIA_LINK_SECRET`: required when `SMEM_ENV` is `prod`/`production` (the API refuses to start without it, error names the variable, never its value); in `dev`/`test` unset means a random per-process secret and one WARN line ("photo links stop working when the API restarts"). That random value is **not** a dev shortcut (nothing is guessable), so it is not registered in `docs/dev-shortcuts.md`. Source `SM` (Secrets Manager) in `docs/production-config.md` (the doc test must pass), and listed for the one-off task definition (T-022) only if that list names API secrets (it does not: the migrate task never serves photos).
3. **Revoke.** One migration (expand-only, goose, `_tab` conventions): `ALTER TABLE yearbook_tab ADD COLUMN link_epoch INT UNSIGNED NOT NULL DEFAULT 0`. `POST /api/yearbook/revoke-photo-links` `{id}` (session, owner only; other user's or missing is `ERROR_NOT_FOUND`) increments it atomically and answers `data: {}`. Every link made before stops working at once (they carry the old epoch). Limiter `revoke_links` 10 per hour per user, fail open.
4. **Public endpoint.** `GET /api/public-media/get-content?token=` (no session, no cookies set, namespace `public-media`, `x-auth: public`). Steps: parse the token (malformed is the same 404), load the media row and its yearbook, recompute the MAC with the yearbook's **current** `link_epoch`, compare in constant time, then require that the photo is **still shareable**: it is that yearbook's cover or profile photo, or it belongs to a note of that yearbook whose status is `approved`. Anything else (bad token, unknown media, pending/hidden note, deleted note, deleted book, deleted media, wrong epoch) answers **the same** `404 ERROR_NOT_FOUND` with the same body and similar timing (no oracle).
5. **Response.** The `display` variant only (the re-encoded image, never the original); reuse the content-writing path of `media/get-content` so `HEAD`, `Range`, `ETag` and `If-None-Match` behave the same. Headers: `Content-Type` from the database, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline`, `Cache-Control: public, max-age=300` (a revoked link can still be served from a cache for up to 5 minutes: state it in `docs/media.md`), `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: cross-origin`. Verify with a test that the served bytes carry **no EXIF/GPS** (the pipeline re-encodes; if it does not strip a marker, strip it here and say so in the PR).
6. **Abuse limits** (`docs/redis.md` table updated): `public_media_miss` 60 per 15 minutes per IP, only misses count, fail open; `public_media_all` 600 per 15 minutes per IP, fail open. The per-route timeout and the processing-slot rules of `get-content` apply.
7. **No token in logs.** The request logger and error logs must never contain the token or the secret (route label only, no query string). A test starts a request with a recognisable token and greps the captured log output. Add an ops note to `docs/media.md` for T-023/T-024: CloudFront and ALB access logs record query strings, so those logs hold bearer tokens and need the same care as the logs of `public-collect`.
8. **Metrics.** `smem_public_media_requests_total{result="ok|not_found|rate_limited"}` (no labels with ids or tokens).

#### Acceptance criteria
- [ ] AC1 — Token unit tests: round trip, tampered MAC, tampered media id, wrong yearbook, wrong epoch, truncated and oversized tokens, constant-time compare helper used.
- [ ] AC2 — Integration: approved note photo, cover and profile photo are served anonymously (no cookie in the request, none in the response); pending, hidden and deleted-note photos, a deleted book, a deleted media row, another book's media with this book's MAC and a bumped epoch all answer the identical 404; `revoke-photo-links` makes a previously served link 404 and a new token (epoch+1) 200; another user's book is `ERROR_NOT_FOUND`.
- [ ] AC3 — The prod config refuses to start without `SMEM_MEDIA_LINK_SECRET` or with fewer than 32 decoded bytes; dev/test start with a WARN; the secret never appears in logs, errors or `/metrics`.
- [ ] AC4 — No EXIF/GPS in the served bytes (fixture with GPS EXIF uploaded through the normal pipeline).
- [ ] AC5 — Limiter tests (miss counter, all counter, fail open when Redis is down with one ERROR per minute as the other open limiters); the 404 body is byte-identical for every failure kind.
- [ ] AC6 — `api/openapi.yaml`, `web/src/api/schema.d.ts`, the Postman collection (anonymous request, revoke, tampered token; the collection runs twice), `docs/media.md`, `docs/redis.md`, `docs/production-config.md` updated; migration applies and rolls forward on a database with data; `make lint test test-integration` green.

#### Risk
`high`: a new anonymous endpoint that serves third parties' photos, a new secret, a migration. The owner approves the merge (`team approve`). The owner already accepted permanent public links (D-32); the controls in requirements 1-7 are the conditions of that acceptance.

#### Test plan
QA probes: token tampering (every byte position of the MAC), replay after revoke, a hidden note's photo, a note hidden after a link was handed out, brute-force pacing against the limiter, HEAD and Range, 10 MiB photo, a revoked link behind a cache (max-age 300), log and metrics scraping for the token, restart in dev (links die, WARN shown), prod start without the secret.
