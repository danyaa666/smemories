# E09_T-141 — Design model and API: manifest design block, book_design_tab, book-design endpoints

**Epic:** E09-customisation-editor · **PRD:** [PRD](PRD.md) "Stage 1 plan" · **Milestone:** M1b · **Risk:** low · **Priority:** P2 · **Type:** feature
**Depends on:** none. **Read first:** PRD "Stage 1 plan", decisions D-24 and D-41, docs/templates.md ("Note fields and html manifests"), `internal/templates` (load.go, spec.go, validate.go, embed/memory-book.json), `internal/yearbook` (owner checks, template change, ChildPurger), `internal/bookdata` and `GET /api/book-data/get`, docs/api-contract.md, docs/db-conventions.md, docs/go-conventions.md, the `be-*` skills in `.agents/skills/`.

#### Requirements (SHALL)
1. **Manifest `design` block** (html templates only; the validator rejects it on Go-renderer templates): `themes` (1..8 ids), `font_sets` (1..6 ids), `sections` (each `{id, hideable, movable, fixed: "first"|"last"|null}`, ids unique), `texts` (each `{id, max}` with `max` 1..200 runes), `images` (each `{id, choices: [ids]}`, 1..8 choices). Ids match `[a-z0-9._-]{1,40}`. The first theme, font set and image choice is the default. Add the block to `memory-book.json` for the pilot: themes `lavender` (today's colours), `peach`, `mint`; font sets `playful` (today's Nunito / Baloo 2 / Patrick Hand) and `classic`; sections `cover` (fixed first), `profile` (hideable, movable), `notes` (movable), `back` (fixed last, hideable); texts `cover.title`, `cover.subtitle`, `profile.heading`, `notes.heading`, `back.message` (use the real strings the component prints: read memory.tsx and list what is fixed text there, max lengths from the layout); images `cover.pattern` with choices `dots` (today's), `plain`, `waves` (only `dots` exists as a file today: ship `plain` as "no pattern" and ask for `waves` as a second small image if you can make one, else leave it out and say so). `templates.Design(id)` returns the parsed block (ok false for none).
2. **Migration** `book_design_tab`: `id`, `yearbook_id` (unique), `template_id`, `options_json` (JSON text, at most 4096 bytes), `created_at`, `updated_at` (BIGINT ms), no FK; expand-only, with a Down. Register the orphan pair in `dbtest.orphanPairs`; delete the row with the yearbook (ChildPurger).
3. **Options document** (version 1): `{"v":1,"theme":id,"fonts":id,"sections":{"order":[ids],"hidden":[ids]},"texts":{id:string},"images":{id:choice}}`, every key optional. Validation against the book's current template manifest: unknown theme/font/section/text/image/choice ids rejected with `ERROR_INVALID_DESIGN` (400) naming the field; `order` must contain every section exactly once and respect `fixed`; `hidden` only `hideable` sections; texts are NFC-normalised, trimmed, no control characters or newlines, 0..max runes (empty string = use the default); total size ≤ 4096 bytes; unknown top-level keys rejected.
4. **Endpoints** (owner only; non-owner and unknown book 404; `/api/<namespace>/<action>`, `{status,data}`): `book-design/get?yearbook_id=` returns `{template_id, options (or null), updated_at}` and the template's design block so the screen needs one call; `book-design/update` (body `{yearbook_id, options}`, full replace, creates the row); `book-design/reset` (deletes the row, idempotent). Rate limits like other owner writes. Changing a yearbook's template (existing `yearbook/update`) deletes its design row in the same transaction.
5. **`book-data/get`** carries `design`: the stored options **resolved** against the manifest (defaults filled, unknown or stale ids dropped silently on read, `template_id` mismatch ignored) so the web never needs the manifest to print. Additive in openapi.
6. openapi + regenerated `web/src/api/schema.d.ts`, Postman folder `book-design`, `docs/templates.md` (new section "Design block and book designs") and `docs/api-contract.md` if needed; an ADR is not needed, the PRD section is the decision record.

#### Acceptance criteria
- [ ] AC1 — The design block validates (a table-driven test with every rejection above); memory-book's block passes; a Go-renderer template with a `design` block fails.
- [ ] AC2 — The endpoint matrix: owner reads/writes/resets; another user and anonymous get 404/401; unknown yearbook 404; the row follows the yearbook delete and a template change.
- [ ] AC3 — Option fuzz: oversized, wrong types, duplicate or missing section ids, `fixed` violations, hidden non-hideable, long and control-character texts, 5000-rune text: all rejected, nothing stored.
- [ ] AC4 — `book-data/get` returns a resolved design; a stored design that names a theme the manifest no longer has resolves to the default.
- [ ] AC5 — `go test -race ./...`, lint, vet incl. `-tags integration`, `scripts/check-class-matrix.sh` unaffected; D-37: start the full CI by hand and quote the run id.

#### Test plan
QA fuzzes the options document and the ids, tries IDOR on every endpoint with a second account, and checks the cascade on yearbook delete and template change.
