# E09_T-161 — Editor text boxes: add, type in place, font, size, colour, align (web)

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low · **Priority:** P2 · **Type:** feature
**Depends on:** T-160 (selection, gestures and keyboard exist; this task plugs text into them). **Read first:** `docs/adr/0004-layout-editor.md` (Q3 in full, risks 1, 6 and 7, "Changes this implies" 4), the spike `docs/spikes/editor/src` (textarea overlay, rune cap, caret restore), `web/src/book/fit.tsx` (`FitText`, `fitElement`), `web/src/book/fitReport.ts`, `web/src/book/layout/runtime.tsx` (how text items are drawn), `web/src/book/editor/document.ts` (`addItem`, `setText`, `textRefusal`, `MAX_TEXT`), the T-159 selection overlay and property panel.

#### Why
Free text is the feature students ask for first: a title, a joke, a caption. Vietnamese is the highest-risk part of the whole editor (ADR risk 1): Telex and VNI build a letter from several keystrokes, and a text field that rewrites its value mid-composition destroys the word. The ADR chose a plain `<textarea>` laid exactly over the printed text, so the browser's own input handling does the typing and the printed text stays what prints.

#### Requirements (SHALL)
1. **Add a text box**: toolbar button "Add text" (and the same in the empty-selection property panel) calls `addItem` with a text item of the manifest's default style (`font` `body`, `size` the manifest's middle size, `color` the first token, `align` left, `bold` false, text "Your text" via i18n), centred on the edited page, selected, and already in edit mode. Refused at 40 items per page kind or 150 in total: a clear message from the refusal, nothing added.
2. **Edit in place**: double-click (or Enter, or tapping an already selected text item) opens edit mode. In edit mode a transparent `<textarea>` lies exactly over the printed text: same box, font, the size the fit rule chose, line height, padding, rotation (it sits inside the rotated item, so the rotation comes from the ancestor) and wrapping, so that the edit view equals the printed view pixel for pixel (the spike proved 0 pixels difference in all 10 cases; keep a parity test). The printed text stays a `div` rendering React text with `white-space: pre-wrap`, never HTML.
3. **The 500-rune cap is in code points** (`MAX_TEXT`, same function the T-158 `textRefusal` uses, same count as the server). While a composition is running (`compositionstart` to `compositionend`) the value is never rewritten and the cap is not applied; at `compositionend` the value is cut to 500 code points. Outside composition, a value over the cap is cut at once and the caret is restored to where the user was typing (ADR "Cap while typing in the middle", the spike's `cap_rewrite_caret_after_typing_in_middle`). `maxlength` is not used (it counts UTF-16 units).
4. **Paste is plain text**: an explicit paste handler takes `text/plain` only, turns `\r\n` and `\r` into `\n`, inserts at the selection and applies the cap. Pasting HTML (bold, sizes, links) inserts none of the markup. Drag-and-drop of rich text into the field is refused the same way.
5. **History**: typing is one undo step per burst, committed on blur, on Escape and when edit mode closes (ADR "Changes this implies" 2); the textarea keeps its native undo while focused, and Ctrl/Cmd+Z inside the field never reaches the editor's own undo. Style changes (requirement 6) are one step each.
6. **Style controls** in the property panel for a text item: font (the manifest's `text_fonts`, shown by their display names), size (pt, a number input and a slider within the manifest `text_size` min and max), colour (a swatch row of the manifest's `colors` tokens, with names for screen readers), align (left, centre, right), bold. All through `setText`; values outside the manifest ranges are impossible to enter (the input clamps and says so).
7. **Too-long text**: the box is fixed. The text shrinks by the existing `fitElement` rule (0.5 px steps) down to 50 % of the box's own size, then clips. In the clip state the editor shows the warning "text is cut" next to the field and in the panel (the book's fit report, `fitReport.ts`), and the textarea stays `overflow: hidden` with a visible caret (ADR "The clip state and the caret"). The fit function re-runs when `document.fonts` is ready and on `loadingdone` (as `FitText` does), so the first paint with a web font that has not loaded yet is corrected.
8. **Focus and mobile**: the field has a text-field role with an accessible name ("Text of the box"); the font size of the real textarea never goes below 16 css px on a coarse pointer (iOS Safari would zoom the page); if the shown size is smaller, scale the whole field with a transform instead of lowering its font size. Escape closes edit mode and keeps the text; clicking outside closes it as well.
9. **Fallback (ADR Q3)**: if the manual checks of AC3 fail on a browser, the property panel always has a normal multi-line text field with the same cap and paste rules, so text can still be changed there on every device. Build this field in any case: it is also what the phone mode (later task) uses, and it is the only way to edit text when the item is hidden behind another one.
10. **Empty and whitespace**: an empty text box is allowed while editing; when edit mode closes with only whitespace the item is removed (one undo step restores it) so the page does not collect invisible boxes.
11. **Tests**: unit tests for the rune counter (ASCII, Vietnamese precomposed and decomposed, emoji, flag emoji, zero-width joiner), the cap-at-compositionend logic and the paste normaliser; a component test with `compositionstart`/`update`/`end` events that proves the value is not rewritten mid-composition; a Playwright spec `tools/e2e/editor-text.spec.mjs` (add a box, type "Việt Nam" through CDP `Input.imeSetComposition` as the spike does, undo, redo, cap 500 with 600 pasted emoji, HTML paste, edit-view-equals-print parity in Chromium on A5, A4 and Letter). Strings through i18n in vi and en (`lint:i18n` green).
12. **Docs**: `docs/` gets a short section "Text boxes in the editor" (the rune count rule, the composition rule, the paste rule, the clip warning, the manual-check table).

#### Acceptance criteria
- [ ] AC1 — The unit, component and Playwright tests pass; the parity test shows the edit view and the printed view with 0 changed pixels (or at most 0.2 % if only glyph anti-aliasing differs, numbers in the PR) for short, medium, long, 500-rune and clipped text, rotated 0 and -4 degrees, on A5, A4 and Letter.
- [ ] AC2 — Composition never loses a letter in the automated test ("Việt", "đường", "Nam" typed key by key through CDP), including at 499 runes (finishes the word, then cut to 500 at `compositionend`).
- [ ] AC3 — **Manual checks, written in the PR and repeated by QA where QA has the device** (each is "pass / fail / not run" with browser and OS): (a) macOS Safari or Chrome with the **Telex** input source: type "Tiếng Việt có dấu" in a new text box, undo, redo; (b) iOS Safari (real iPhone or the simulator): focus does not zoom the page, Telex/VNI keyboard builds the letters, the box stays visible; (c) Firefox desktop typing and paste; (d) Android Gboard Telex if a device exists. Anything "not run" is listed as unproven in the PR and in `docs/`, never as passing. A failure of (a) or (b) blocks the merge (the leader then switches the task to the requirement 9 fallback only).
- [ ] AC4 — HTML paste inserts no markup; 600 pasted emoji give exactly 500 code points; Ctrl/Cmd+Z inside the field undoes typing in the field only.
- [ ] AC5 — The clip warning appears for text that does not fit at 50 %, and goes away when the text is shortened or the box is made larger; the same state shows in print-check output unchanged (`make print-check` green).
- [ ] AC6 — Lint, prettier, tsc, vitest, `lint:i18n`, `check:api`, build, `make e2e` (incl. `editor-text.spec.mjs`) and `make print-check` green; no new dependency; nothing under `.team/`.

#### Test plan
Dev: the tests of requirement 11 and the manual table with real keystrokes where the dev has a machine (an agent without a keyboard marks (a) to (d) "not run"). QA: runs everything on the PR head, repeats the parity numbers, types Vietnamese through the CDP path in a second browser engine if available (Playwright Firefox, WebKit), pastes odd content (very long line without spaces, a lone surrogate, RTL text, a URL, tabs), tries adding the 41st box, deletes a box and undoes it. The leader asks the owner to run AC3 (a) and (b) by hand (owner item) before the stage 2 exit check.
