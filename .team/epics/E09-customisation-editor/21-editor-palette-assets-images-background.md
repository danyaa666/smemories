# E09_T-162 — Editor palette: stickers, shapes, frames, own images and the page background (web)

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low · **Priority:** P2 · **Type:** feature
**Depends on:** T-161 (the property panel and toolbar it extends; start after T-161 is merged to avoid a conflict round). **Read first:** `docs/adr/0004-layout-editor.md` ("Changes this implies" 3 and 6), `docs/assets.md` and `web/src/book/assets/index.tsx` + `registry.json` (T-151), `web/src/api/schema.d.ts` (`media/create` with `purpose=design`, `media/get-list`, media delete, `book-layout/save` errors), `web/src/book/editor/document.ts` (`addItem`, `setBg`, `removeItem`, `reorderItem`), `web/src/book/layout/runtime.tsx` (how `asset`, `image` items and the background are drawn), the T-159 property panel, the T-160 selection and keyboard code.

#### Why
The editor can move things and type text. Students now want to decorate: a sticker, a frame around a photo, their own picture as a page background. The server side exists (asset registry T-151, design-image uploads T-152, layout validation T-153); this task is the screen for it.

#### Requirements (SHALL)
1. **Palette** (a side panel next to the property panel, tabs or sections): *Stickers*, *Shapes*, *Frames*, *My images*, *Background*. Assets come from the registry with `label_vi`/`label_en` by the UI language, a search field over label and tags (diacritic-insensitive: "nang" finds "nắng"), a grid of thumbnails (`AssetSvg`, lazy for large lists), keyboard reachable (arrow keys in the grid, Enter adds). Each tile has an accessible name (the label).
2. **Add to the page**: click or Enter adds an `asset` item (`addItem`) on the edited page, centred, 25 % of the page width, keeping the SVG's aspect ratio, on top of the z-order, selected. Refused at 40 per page kind / 150 total with a clear message. A frame is added the same way (a frame is just an asset; "behind the photo" is the z-order buttons). Drag from the palette onto the page is **not** in scope.
3. **Asset controls** in the property panel: for a tintable asset a colour swatch row of the manifest `colors` tokens plus "original colours" (clears `tint`); non-tintable assets show no tint control. Duplicate (button and Ctrl/Cmd+D, offset by 3 % of page width) and delete already exist or are added here for all item kinds; one history step each.
4. **My images tab**: lists the yearbook's design images (`media/get-list` with `purpose=design`, thumb variant, keyset paging with "load more"), an "Upload image" button and a file drop zone (JPEG, PNG, WebP; the client checks type and the 10 MiB request cap before sending, but the server stays the judge). Upload shows progress and can be cancelled; the answer's errors are explained in plain words in vi and en: unsupported or corrupt image, too large, the 30-image cap (with the count), the 500 MiB quota, `ERROR_RATE_LIMITED`/`ERROR_BUSY` (retry-after shown), email not verified (link to the existing verify flow), offline. No upload starts twice from a double click. A phone camera photo (4000 px) works (the server resizes).
5. **Add an image**: click adds an `image` item at the image's aspect ratio (long side 50 % of the page width), `fit` `contain` by default, selected. Property panel for an image item: fit (cover / contain), corner radius (0..500 as a slider with the shown value), "replace image" (picks another design image or uploads a new one, keeping the box), preview of the file name is **not** shown (the client file name is never stored).
6. **Page background** (the *Background* tab and the nothing-selected panel): a swatch row of the manifest `colors` tokens, none, any registry asset of kind `shape`/`sticker` used as a full-page background, or one of the design images (`bg.media`, shown full-bleed); each choice is one `setBg` step; "remove background" clears it. The background is per page kind (cover, profile, notes, back) as in the model; a note says which page kind the change applies to, with one extra action "apply to all page kinds" (one history step per kind or one grouped step: your choice, documented).
7. **Deleting a design image that is in use**: the server refuses a layout that points at a missing image, and undo could bring such a layout back. So: if the image is used on any page (item or background), the confirm dialog says where ("used on 2 pages"); on confirm the editor (a) applies one op that removes every item and background that uses it, (b) waits for that save to settle (`store.settle()`), (c) deletes the image, (d) **clears the undo and redo stacks** and says so in the dialog text. If the delete call fails after (b), the layout stays without the image (nothing is lost on the server; the image stays in the list); show the error. An unused image deletes with a plain confirmation and keeps the history.
8. **Missing or foreign image id in a loaded layout** (the reader ignores it): the editor shows the item as a "missing image" placeholder that can be selected and deleted, and the save of a layout that the server rejects with `ERROR_INVALID_LAYOUT` shows the problem list in the existing `invalid` state with a button that removes the offending items (paths from `data.problems`).
9. **Limits and cost**: thumbnails load as `thumb`, the page shows the `display` variant; images not yet visible are not fetched (lazy); at most 4 uploads in flight client-side (the server allows 2 per user: queue the rest). No new dependency. Nothing is fetched from a third party.
10. **Accessibility and i18n**: every control has a label and a keyboard path; the palette follows the tab order of the editor; the live region announces "added", "removed", "upload finished"; all strings in vi and en (`lint:i18n` green). Contrast of the tiles' selection state meets the existing tokens.
11. **Tests**: unit tests for the search normaliser, the add-item defaults (size, aspect, z-order, limits), the delete-in-use sequence (ops and history clear, using a fake API), and the upload state machine (progress, cancel, each error mapped); component tests for the palette grid keyboard use; a Playwright spec `tools/e2e/editor-palette.spec.mjs` (add a sticker and a frame, tint, add a shape background, upload a real PNG design image through the UI, add it as an image and as a background, replace it, delete it while in use and see the pages cleaned, reload and see the same layout, the 31st upload refused with the cap message), on the Memory Book cover and profile pages. Print-check: one fixture page with an asset, an image and a background proves that the print route draws them (existing print-check mock repaired in T-154 can be extended).
12. **Docs**: `docs/` section "Palette, images and backgrounds in the editor" (what the tabs do, the delete-in-use rule and why history is cleared, limits, errors, the licence note that every asset has a licence file).

#### Acceptance criteria
- [ ] AC1 — A student adds a sticker, a shape and a frame, tints a tintable one, uploads their own image through the UI, uses it as an image item and as a page background, reloads and sees the same page; the print route (`/book`) draws the same (print-check test green).
- [ ] AC2 — Every upload error in requirement 4 shows its own message (unit-tested; the 30-cap and an unsupported file also in Playwright).
- [ ] AC3 — Deleting an image that is in use removes its items and background, the server never receives or keeps a layout with the deleted id (check `book-layout/get` after), and undo cannot bring it back; deleting an unused image keeps the history.
- [ ] AC4 — Keyboard-only: find a sticker by searching "nang" or a Vietnamese label, add it with Enter, tint it, move it with the keys of T-160, delete it.
- [ ] AC5 — 40-item and 150-item limits are explained, not silent.
- [ ] AC6 — Lint, prettier, tsc, vitest, `lint:i18n`, `check:api`, build, the e2e suite (incl. `editor-palette.spec.mjs`) and `make print-check` green; no new dependency; nothing under `.team/`.

#### Test plan
Dev: the tests of requirement 11 on a private compose stack (non-default ports; `scripts/e2e.sh` directly, see `docs/e2e.md`). QA: runs everything on the PR head; uploads odd files (a 12 MiB image, a GIF, a renamed text file, a truncated PNG, a 4000 px phone photo, a PNG with transparency as a background), hits the cap and the rate limit, deletes an in-use image with two tabs open (the second tab's next save must not resurrect it: expect the conflict banner), tries the 41st sticker, searches with and without diacritics, walks the palette by keyboard, and checks the printed `/book` of a book that has an image background.
