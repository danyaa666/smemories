# E09_T-165 — Editor version history panel: list, preview and restore (web)

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low · **Priority:** P2 · **Type:** feature
**Depends on:** T-163 (the three routes `book-layout/version-list|version-get|restore` must be merged; start after that). **Read first:** `docs/api-contract.md` (book-layout section as updated by T-163), `docs/templates.md` (history paragraph), `web/src/api/schema.d.ts`, `web/src/book/editor/store.ts` (`settle()`, `base_version`, conflict state), `useLayoutEditor.ts`, `history.ts`, `SaveStatus.tsx`, `EditorShell.tsx`, `PropertyPanel.tsx`, `web/src/book/layout/runtime.tsx` (how a layout is drawn read-only).

#### Why
T-163 stores up to 30 snapshots per book. Without a screen they are worthless: the student who ruined a page at midnight must see "how it looked yesterday evening", compare, and go back in two clicks, without losing today's work by accident.

#### Requirements (SHALL)
1. **Entry point**: toolbar button "History" (vi/en, icon + text) opening a side panel (or dialog on phone widths) over the property panel; Esc closes it and returns focus to the button. The button is available to the owner only (the editor already is).
2. **List**: calls `version-list` when the panel opens (never on editor load); shows up to 30 rows newest first: relative time ("12 minutes ago", locale aware) with the absolute time as a title, a kind label ("Autosave", "Before reset", "Before restore"), and the item count. Loading, empty ("No earlier versions yet. They appear as you edit."), error-with-retry and offline states. The list is not polled; a "Refresh" action re-calls it.
3. **Preview**: selecting a row calls `version-get` and shows that layout **read-only** in the editor's stage (same renderer as the page, no handles, no panel edits, a visible banner "Previewing a version from <time> — your current work is unchanged" with the buttons *Restore this version* and *Back to current*). Items that point to an asset or design image that no longer exists render as the reader does (ignored); the preview says "N items will be dropped" using the missing-id count the client can compute from the asset registry and the design-image list it already holds (a hint only; the server's `dropped` is the truth). The page strip works in preview mode (the student can look at every page kind). Keyboard: arrow keys move through the rows, Enter previews, Esc leaves the preview.
4. **Restore**: *Restore this version* first runs `store.settle()` (flushes in-flight and queued saves, so the server's current version is the editor's), then calls `restore` with `base_version` = the store's current version. On success the editor **adopts** the answer (`layout`, `version`), clears the undo and redo stacks (the answer does not descend from the old history; say so in the confirm text), leaves preview mode, and announces "Version restored" plus, when `dropped > 0`, "N items could not be restored because their image or sticker no longer exists" in the live region and a visible toast. The replaced current document is kept by the server as a `restore` snapshot, so the confirm text says "Your current version is kept in the history".
5. **Errors** (vi and en, each with its own message): `ERROR_VERSION_CONFLICT` (another tab saved: show the conflict banner flow the editor already has, with the stored document; nothing is overwritten), `ERROR_INVALID_LAYOUT` (the version no longer fits the template; offer *Back to current*), `ERROR_VERSION_TEMPLATE_CHANGED`, 404 (version gone, e.g. pruned meanwhile: refresh the list), rate limit/busy (retry-after), offline. A failed restore leaves the editor, its history and its autosave exactly as before.
6. **Guard rails**: while previewing, autosave keeps running for pending edits only; the preview itself never creates a save, and the gesture/keyboard handlers of the editor are inactive (no accidental drag on a preview). Closing the panel while previewing returns to the current document. A restore button double click sends one request.
7. **Cost**: `version-get` is fetched once per selected row and cached for the open panel (bodies up to 128 KiB each; keep at most 5 in memory). No call is made until the panel opens. No new dependency.
8. **Accessibility and i18n**: the list is a listbox/radio group with accessible names; the preview banner is a status region; the panel is reachable in the editor's tab order; all strings in vi and en (`lint:i18n` green).
9. **Tests**: unit tests for the list model (relative time boundaries, kind labels), the preview/restore state machine with a fake API (settle first, base_version from the store, adopt, history cleared, every error mapped, double click once), the missing-id hint; a component test for keyboard navigation; Playwright spec `tools/e2e/editor-history.spec.mjs` on the real stack: make three edits spaced by the server clock allowance (use the test hook or the direct DB timestamp helper T-163 provides; document how), open History, preview an earlier version, restore it, reload and see it persisted, undo does nothing afterwards, a second tab restoring at the same time gives one conflict, a version that used a deleted design image restores with the dropped message.
10. **Docs**: `docs/` section "Version history in the editor" (what is kept and for how long as per the L-17 rule, preview vs restore, why undo is cleared, errors), and the manual-check note for phone widths.

#### Acceptance criteria
- [ ] AC1 — A student edits a page in three bursts, opens History, previews an older version, sees the page unchanged underneath after *Back to current*, restores it, reloads and sees the restored layout; the replaced layout appears as a new "Before restore" row.
- [ ] AC2 — Restore with a deleted design image shows the dropped count in the toast and live region; the restored layout never references the deleted image (check `book-layout/get`).
- [ ] AC3 — Every error in requirement 5 has its own vi/en message (unit-tested; conflict and dropped also in Playwright); a failed restore changes nothing.
- [ ] AC4 — Nothing is fetched before the panel opens; the list shows at most 30 rows; the preview cache keeps at most 5 bodies.
- [ ] AC5 — Keyboard-only walk: open History, move through the rows, preview, restore, Esc returns focus to the History button.
- [ ] AC6 — Lint, prettier, tsc, vitest, `lint:i18n`, `check:api`, build, the e2e suite (incl. `editor-history.spec.mjs`) green; no new dependency; nothing under `.team/`.

#### Test plan
Dev: the tests of requirement 9 on a private compose stack (non-default ports, `scripts/e2e.sh` directly, `docs/e2e.md`). QA: runs everything on the PR head, creates 31+ snapshots (DB timestamps) and checks the list stops at 30, restores several versions in a row, restores while an autosave is pending (the pending edit must not be lost or reordered), tries two tabs, deletes a design image then restores a version that used it, checks a phone width, and checks the Network tab: no `version-*` call before the panel opens.
