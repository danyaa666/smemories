# E09_T-167 — Class book carries each member's layout (server cap, privacy, web wiring)

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low on the board (the board knows only low/high; the admin's read right was decided in D-36/D-43/D-44) but treat it as medium: it touches permissions and a response-size cap, so QA must run the full integration suite, the class matrix and the print-check, with result lines · **Priority:** P2 · **Type:** feature
**Depends on:** T-153/T-154/T-156 (merged: layout model, runtime, version counter). Independent of T-165/T-166 (no shared files except docs). **Read first:** `internal/class/book.go` (the 8 MiB cap, `strippedMemberMax`, `BookMember`, `Encode`, the member loop in the service), `internal/class/book_cap_boundary_test.go`, `internal/class/book_integration_test.go`, `internal/booklayout` (service `Get`, validate), `docs/class-privacy-review.md` (rows for design images, `media/get-content`, the matrix section), `docs/class-permissions.md`, `docs/api-contract.md` (class-book/get), T-146 (how `design` got into `BookMember` and into the cap: copy that pattern), the web class book (`web/src/book/` class book component, T-154 AC4 narrowing), `docs/templates.md`.

#### Why
T-154 made the web class book draw `member.layout` when present, but `class-book/get` does not send it, so a student's free layout appears in their own book and print but not in the class book their admin prints. Until this task the editor would promise something the class book silently drops.

#### Decisions already taken (do not reopen)
D-36 (class yearbook, members' linked pages), D-43/D-44 (the class admin reads students' referenced design images through the narrow admin read path; the privacy review gets updated). This task is that update for the layout itself.

#### Requirements (SHALL)
1. **Wire**: `BookMember` gets `layout` (the stored layout document of the member's linked yearbook, `null` when none or when it no longer validates against the member's current template manifest and asset registry; same read rule as `book-data/get`). The service reads it **as the book's owner** (member row's user), like `design`, through the booklayout service; no new SQL path that bypasses its validation. Only the document is sent: no version number, no history, no snapshot ids, no `template_id` beyond what `yearbook` already carries.
2. **Cap**: the 8 MiB `MaxBookBytes` still holds with layouts (a layout is up to 128 KiB, 60 members: 7.5 MiB alone would starve the notes). Rule (the leader's choice, document it): a member's layout is included **before** their notes; if including it would leave the remaining members unable to keep their `strippedMemberMax` reserve, the layout of that member (and of later ones) is dropped instead of the notes, and the member ids are listed in a new `truncated_layouts: []` array of the response (`[]` for a normal class). `strippedMemberMax` keeps meaning "a member with no notes and no layout" so the reserve proof is unchanged; extend the worst-member unit test and the boundary test with maximal layouts. A normal class (layouts of a few KiB) loses nothing.
3. **Privacy**: the layout contains the text the student typed and ids of their own images. It is sent only inside `class-book/get` to the class admin and members who already may read that member's profile and approved notes in the class book (no wider audience than the page's existing class-book exposure; check who can call the route today and say so in the docs). Design-image bytes keep flowing through `media/get-content` limited to images **the member's layout references** (already built in T-152/T-153): add a test that an image the member removed from the layout is no longer readable by the admin, and that a member with `linked=false` or a departed member exposes no layout. Update `docs/class-privacy-review.md` (a row for the layout in the "what the admin sees" table, the cap/`truncated_layouts` note, section 8 sign-off list stays an owner item), `docs/class-permissions.md` and the matrix row of `class-book/get`; the class matrix test must stay green.
4. **Observability**: the existing class-book log line gets the number of layouts included and dropped (counts only, no content, no ids); one counter for dropped layouts.
5. **Web**: the class book already draws `member.layout` (T-154 AC4); make it work with the real field: the layout of member A never draws on member B's pages; a member whose template differs from another's draws with their own manifest; `truncated_layouts` members draw as without a layout and show the same subtle "layout not included" note the class book uses for truncated notes (reuse its component and i18n pattern, vi and en); `web/src/api/schema.d.ts` regenerated (`check:api` green). Print route and PDF of the class book draw the layouts (print-check fixture: two members with different layouts and one dropped).
6. **Tests**: unit (cap rule with layouts at the boundary, worst member, order layout-before-notes, `truncated_layouts` content, template-mismatch read → null); integration (real MySQL: a class of 3 members with layouts, admin sees them, a member who unlinks or leaves loses theirs, removed image unreadable, non-members 404, `-race` where the package has it); class matrix; the Postman collection step for `class-book/get` asserting the real envelope including `layout` and `truncated_layouts`; Playwright extension of the existing class e2e (`tools/e2e/`, find the class book journey): admin opens the class book and sees a member's moved title and sticker, prints it.
7. **Docs**: `docs/api-contract.md` (the two fields, the cap rule), `docs/templates.md` (class book paragraph), the privacy docs above, `docs/e2e.md` if commands change.
8. No new dependency; nothing under `.team/`; no migration.

#### Acceptance criteria
- [ ] AC1 — The class admin's class book shows each linked member's layout (moved elements, stickers, text, background, image) on that member's pages only, on screen and in the printed PDF; members without a layout are unchanged.
- [ ] AC2 — A class where every member has a 128 KiB layout and 40 long notes still answers at most `MaxBookBytes`; layouts are dropped (listed in `truncated_layouts`) before the cap is passed and never push the body over; a normal class loses nothing (tests at the boundary).
- [ ] AC3 — Privacy tests: unlinked/departed member exposes no layout; a layout never leaves another route; an image removed from the layout is no longer readable by the admin; the class matrix is green and its rows updated.
- [ ] AC4 — Lint, vet, `go test -race ./...`, `make test-integration`, the web checks (lint, prettier, tsc, vitest, `lint:i18n`, `check:api`, build), the Postman run, the class e2e and `make print-check` green; result lines in the PR with counts.
