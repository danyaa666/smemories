# E09_T-173 — Own page templates and the apply API (Go): save my page, apply a template per section

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** high (new table and migration, owner data, permissions, concurrency, account deletion and export hooks): needs the owner's `approve` before merge · **Priority:** P2 · **Type:** feature
**Depends on:** T-172 (model, shipped storage, `template-list`). **Read first:** ADR 0005 Q3 and Q8 task 4 (PR #165 until merged), T-172 spec (31), `internal/booklayout/*` (service, store, `versions.go` snapshot logic, `ValidateRestore`), migration `20261102120000_book_layout_version_tab.sql` as the model for conventions, `.agents/skills/` backend skills, `docs/api-contract.md`, `docs/db-conventions.md`, `docs/go-conventions.md`, `docs/class-permissions.md`, `docs/class-privacy-review.md`, T-163 spec (22) for the snapshot/lock/clock patterns.

#### Why
Owner request: "save my edited page as my own template" and choosing a template for each section. ADR 0005: a student's own template is a page template stored in one owner-only table; applying one (shipped or own) copies it into the book's layout in **one write with one history snapshot**, so a bad template or a conflict can never leave a half-applied page and "undo" is the existing version restore.

#### Requirements (SHALL)
1. **Table** `book_template_tab` (new goose migration, up and down, expand-only, conventions of `docs/db-conventions.md`): `id` (internal), `public_id` (ULID), `owner_id`, `name` (<= 60 chars, plain text), `kind`, `template_id` (the book template the page was made on), `layout_json` (<= 64 KiB), `item_count`, `bytes`, `created_at` (BIGINT ms). `_tab`, no foreign keys, unique `(owner_id, public_id)`, index `(owner_id, created_at DESC)`.
2. **Routes** in the `book-layout` namespace (owner only; another user's id or a missing id is `ERROR_NOT_FOUND`; `{status,data}`; rate limit like layout saves): `template-create` (`yearbook_id`, `kind`, `name`: copies the book's **current** `pages.<kind>` into a new template; `image` items and `bg.media` are **stripped** (own images are not shareable and are not copied) and the answer says how many were stripped; at most **20 per user** (`ERROR_TEMPLATE_LIMIT`, 409, `data:{limit:20}`) and 64 KiB each), `template-delete` (`id`), and `template-list` extended (from T-172) to return the owner's own templates for the book's template `template_id` and kind (`source: "own"`, with `page`) beside the shipped ones (`source: "shipped"`).
3. **Apply**: `POST /api/book-layout/apply-template {yearbook_id, base_version, kind, source: "shipped"|"own", template_id}` under the book's layout row lock: replaces `pages.<kind>` (`bg`, `overrides`, `items`, nothing else) with the template's page, re-validates the **whole** document like a save (`ValidateRestore` semantics: an asset no longer in the registry is dropped and counted, anything else is `ERROR_INVALID_LAYOUT` with the problem list), writes **one new version** and **one history snapshot of the document before it** (T-163 rules; new snapshot kind `apply`, counted in the retention limit of 30), returns `{version, layout, dropped}` like `restore`. `ERROR_VERSION_CONFLICT` with the stored document on a stale `base_version`. A template made on a different book template than the book's current one is refused (`ERROR_TEMPLATE_MISMATCH`, 409). All or nothing in one transaction. If the book has no layout yet, one is created.
4. **Deletion and export**: own templates are deleted with the account (hook for T-025; add the code path only if the account deletion code exists, otherwise a note on T-025 and a documented test seed) and listed by count in the data export when that exists; deleting a template never changes books that used it.
5. **Privacy and permissions**: templates are never readable by anyone but the owner; class admin and members get 404 on every new route; the class matrix and `docs/class-privacy-review.md` get a row per route.
6. **Observability**: counters for templates created, deleted, applied (labels `source`, `result`: ok, conflict, invalid, mismatch) and stripped items; one slog line per apply (book public id, kind, source, version numbers, `dropped`); no layout content in logs.
7. **Tests**: validation and store unit tests; integration tests on real MySQL for create (stripping, limit 20, size limit), list isolation between users, delete, apply (success, stale version, template mismatch, a dropped asset, invalid page, creates a layout when none, atomicity: a failing validation leaves the document and the history untouched, a snapshot of kind `apply` exists, retention still 30), **concurrency** (two parallel applies: one wins, one conflicts; `-race`, repeated 20 times in the package), cross-user and cross-book 404s, migration up/down, class matrix; Postman steps asserting the real envelope.
8. **Docs**: `docs/api-contract.md` (routes, errors, the strip and dropped rules), `docs/templates.md`, privacy docs, `docs/observability.md`, OpenAPI and regenerated `web/src/api/schema.d.ts` (`check:api` green).
9. No new dependency; nothing under `.team/`; the web UI is a separate task.

#### Acceptance criteria
- [ ] AC1 — Create stores the current page as an own template with images stripped and counted; the 21st is refused; another user's id is 404.
- [ ] AC2 — Apply replaces only the chosen page kind, in one version with one `apply` snapshot; a stale `base_version` conflicts and changes nothing; restoring the snapshot returns the earlier page.
- [ ] AC3 — A failed apply (invalid page, mismatch, conflict) leaves the layout and the history byte-identical; two concurrent applies never both succeed (`-race` x20).
- [ ] AC4 — Matrix and privacy docs updated; class admin, member, other class admin and anonymous are refused on every new route.
- [ ] AC5 — Lint, vet, `go test -race ./...`, full `make test-integration` (default DSN), `make migrate` up and down, `check:api`, the Postman run green; QA writes the result lines (counts, head SHA) in the board comment. The leader merges only after the owner's `approve`.

#### Test plan
QA runs the full integration suite, migration down/up, the matrix and Postman on the PR head; fills 20 templates and tries the 21st; applies shipped and own templates to every kind; races two tabs; checks that deleting a template or an asset does not corrupt books that used them; confirms the 404 cells.
