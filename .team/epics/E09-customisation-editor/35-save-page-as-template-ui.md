# E09_T-176 — "Save my page as a template" (web): name it, see what is kept, use it again

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low (web only; the server rules are T-173) · **Priority:** P2 · **Type:** feature
**Depends on:** T-175 (the Templates panel, the list model and the apply flow it extends), T-173 (`template-create`, limit 20, strip rule). **Read first:** spec 34 (T-175), spec 32 (T-173: strip rule, `ERROR_TEMPLATE_LIMIT` with `data.limit`, 64 KiB), `docs/api-contract.md` (template-create), `web/src/book/editor/HistoryPanel.tsx` and the Templates panel from T-175, `store.ts` (`settle()`), `EditorShell.tsx` (toast, live region).

#### Why
Owner request D-45: "or just can use that page and import to edit as a template". A student who has laid out a page they like must be able to keep it as a template, then apply it again (to the same book, after a reset, or after trying other templates). Images are not copied (they are the student's own and not shareable), so the student must see exactly what is and is not kept, before and after.

#### Requirements (SHALL)
1. **Entry point**: a button "Save this page as a template" (vi "Lưu trang này thành mẫu") in the Templates panel header (T-175) for the current page kind; also reachable by keyboard from the toolbar through the same panel (no second toolbar button). Disabled with a reason ("Nothing to save: this page has no changes yet") when the stored `pages.<kind>` is empty (no overrides, items or background); disabled with the reason while the editor is offline.
2. **Dialog**: name field (required, plain text, at most 60 code points, counter shown, trimmed, default "My <section> <n>" in the locale; code points counted as the server does, Vietnamese composed and decomposed forms both fine); a summary line "This saves the cover as it is now: 5 items, a background. N images are not saved (your own images are not copied to templates)" where the image count is a **client hint** from the current document (the server's `stripped` is the truth and is shown after saving); *Save* and *Cancel*; Enter saves, Esc cancels and returns focus to the button. A name that is empty or too long shows an inline error and does not send anything.
3. **Save**: `store.settle()` first (the server copies the book's **stored** page, so the template must be what the student sees), then `book-layout/template-create {yearbook_id, kind, name}`. Success: close the dialog, announce and toast "Template 'X' saved (own templates: 3 of 20)" plus, when `stripped > 0`, "N images were not saved"; the Templates panel list for the kind is refreshed and the new card is focused and marked "new" for the announcement. The editor's document, undo stack and autosave are untouched (a template save changes nothing in the book).
4. **Errors** (vi and en, each its own message; nothing in the editor changes): `ERROR_TEMPLATE_LIMIT` (409, `data.limit`: "You have 20 own templates; delete one in the panel first" with the panel's own-templates group scrolled into view), `ERROR_TOO_LARGE` (the page is bigger than a template may be: "This page is too big to keep as a template; remove some items"), `ERROR_INVALID_LAYOUT` (problem list not shown, generic message plus *Back*), the name errors the server may send (`ERROR_PARAM`), rate limit/busy (retry-after), offline, 404 (the book is gone). A double click on *Save* sends one request; the dialog stays open on error with the typed name kept.
5. **Round trip**: a template saved here appears in "My templates" of the same book template and kind (T-175 list), previews and applies like any other (including after the page was reset or changed), and does not appear for another kind or for a book on another template (server rule; the e2e checks it).
6. **Counts**: the own-templates group header shows "3 of 20"; at 20 the save button explains instead of opening a dialog that is bound to fail.
7. **Accessibility and i18n**: the dialog is a labelled modal with focus trap and return, the counter is announced politely, all strings in vi and en (`lint:i18n` green), targets at least 44 px on touch widths.
8. **Tests**: unit tests for the name rules (trim, 60 code points boundary with Vietnamese text, empty), the client hint (image items and `bg.media` counted), the save state machine with a fake API (settle first, one request on double click, each error mapped, success refreshes the list and leaves the store untouched), a component test for the dialog keyboard flow; Playwright spec `tools/e2e/editor-save-template.spec.mjs`: move and rotate the cover title, add a Vietnamese text and an image, save as a template, see the "images not saved" note, reload, reset the cover, apply the template from "My templates" and see the title and text back and no image, the History panel shows the "Before template" row, save 20 templates then the 21st shows the limit message, delete one and save again, a book switched to another template does not list it.
9. **Docs**: `docs/editor-templates.md` (extend T-175's: saving a page, what is stripped and why, limits, errors); `docs/e2e.md` if commands change.

#### Acceptance criteria
- [ ] AC1 — A student customises the cover (moved title, a Vietnamese text, an own image), saves it as "Bìa của tôi", sees "1 image not saved", resets the cover, applies "Bìa của tôi" and gets the title and text back at the same places, no image.
- [ ] AC2 — The 21st template is refused with its own vi/en message and the dialog keeps the typed name; deleting one allows the next save.
- [ ] AC3 — Saving a template changes nothing in the editor (document, undo stack, version, autosave); a double click sends one request.
- [ ] AC4 — Name rules at the 60-code-point boundary work for Vietnamese text typed with Telex-style composed and decomposed characters; each error of requirement 4 has its own message (unit-tested; limit also in Playwright).
- [ ] AC5 — Lint, prettier, tsc, vitest, `lint:i18n`, `check:api`, build and the e2e suite (incl. `editor-save-template.spec.mjs`) green; no new dependency; nothing under `.team/`.
