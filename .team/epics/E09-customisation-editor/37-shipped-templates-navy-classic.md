# E09_T-178 — Shipped page templates for Navy Classic: at least four looks per page kind, authored by us

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low (content files plus tests; every file passes the same validator as a student's save) · **Priority:** P2 · **Type:** feature
**Depends on:** T-172 (model, shipped storage, `template-list`; merged), T-171 (shape.rect and shape.ellipse; merged), T-166 (Navy Classic layout; merged). **Read first:** `docs/templates.md` ("Page templates", "Layout block and layout document"), `internal/templates/embed/pagetemplates/navy-classic/` (the four files T-172 shipped and their `LICENCE.txt`), `internal/booklayout/pagetemplate.go` and `validate.go`, `internal/templates/embed/navy-classic.json` (`design.layout`: page kinds, editable ids, `text_fonts`, `colors`, `safe_margin_mm`), `web/src/book/templates/navy.tsx / navy.css` and its CSS, `web/src/book/assets/registry.json` (stickers, shapes, frames; licences), `docs/assets.md`, ADR 0005 Q3 and Q8, `docs/print-check.md` (or the print-check README) for the parity method.

#### Why
The template gallery (T-175) is only worth opening if a student finds real choices per section. T-172 shipped one template per kind as proof of the model. Owner decision D-45 allows Doory templates by build-time conversion, but the licence route is still open (Q-064), and the leader's recommendation is route B: **we author the templates ourselves**, with Doory only as inspiration (look and feel, layout ideas; no Doory file, image or text is copied). Authoring our own needs no licence decision, so this work starts now; converted templates, if the owner picks route A, are added later as separate files.

#### Requirements (SHALL)
1. **Content**: at least **three new templates per page kind** (cover, profile, notes, back) on top of the existing one, so every kind has **four or more**, each a file `<kind>-<name>.json` in `internal/templates/embed/pagetemplates/navy-classic/` with a unique `id` equal to the file name, `label_en` and `label_vi` (natural Vietnamese, short, distinct from each other), `kind`, and `page` (the value of `pages.<kind>` of a layout document). The four looks of one kind must be **clearly different** (placement of the title and the portrait/blocks, background colour, decoration density, rotation/tilt), not recolours of one another. Navy Classic is the formal template (gold frame, navy and cream pages, serif letter): the looks must keep the frame and the formal tone (stay inside the frame's inner rule; ornaments are restrained: gold stars, rules, a seal), ranging from stately to modern-classic.
2. **What a template may contain** (the T-172 rules, restated): overrides of the template's own editable elements (move, resize, rotate, hide), `bg` colour (theme tokens only, no picture), and added **asset items** (stickers, shapes, frames from the registry, tinted with the template's theme tokens) and **text items only when the text is language-neutral** (digits, symbols, a year); **no prose**: a template must never put English or Vietnamese sentences into a student's book. No image items, no external URLs, no user ids. At most 40 items per page; every box inside the page and inside the safe margin the manifest declares, except decoration that is meant to bleed (say which and why in the file comment, if the format allows, else in `docs/templates.md`).
3. **Quality gates in tests** (a template that fails any of them fails the build): validates with `booklayout.Validate` for its book template; `template-list` returns it with both labels; ids and labels unique per kind and book template; **contrast**: every text element a template touches (moved or re-coloured) keeps at least **4.5:1** against the page background colour of that template (compute from the theme tokens with the WCAG formula in a Go test; for a moved element over a sticker, say how the test treats it); no two templates of a kind have the same `page` bytes; labels do not exceed the gallery's card width (max 24 characters, both languages).
4. **Parity and look**: extend `tools/print-check` with a case per shipped template (all kinds, A5, A4 and Letter) rendering the page with real sample data (photos, names, several notes, long Vietnamese names such as "Nguyễn Thị Phương Anh") and applying the existing parity method (screen vs print pixel difference below the standing threshold, each placed item within 2 px). Long names and the notes-page overflow must not break the look: a template for the notes kind must still let the autographs flow (the editable list never includes them).
5. **Contact sheet**: a script (`tools/print-check` or `scripts/`, no new dependency) renders all templates of this book template into one PNG per paper size for the owner to look at; commit the A5 sheet as `docs/images/page-templates-navy-classic.png` (at most 600 KB) and say in the PR how to regenerate the others.
6. **Licences and provenance**: `LICENCE.txt` of the folder is updated: these files are the project's own authoring (state the licence the project uses for its own content as `docs/assets.md` does for authored assets), they use only registry assets whose licences already allow it, and **nothing is copied from Doory or any other template source**; the PR description names the sources of inspiration (links) without copying.
7. **Docs**: `docs/templates.md` lists every shipped template (id, kinds, one-line description), the rules above and how to add one.
8. No new dependency; nothing under `.team/`; no change to the Go model or the API (content only; if a validator limitation blocks a look, stop and comment on the task instead of changing the model).

#### Acceptance criteria
- [ ] AC1 — Every page kind of Navy Classic has four or more shipped templates; each validates and appears in `template-list` with both labels; ids and labels unique.
- [ ] AC2 — The contrast gate and the distinctness gate are in the Go tests and pass; a deliberately bad template (low contrast, duplicated page) makes them fail (show this once in the PR, do not commit the bad file).
- [ ] AC3 — print-check has a case per template on A5, A4, Letter with long Vietnamese names and passes (counts in the PR).
- [ ] AC4 — The contact sheet is committed and shows distinct looks per kind; `docs/templates.md` is updated; no prose text and no image item in any template.
- [ ] AC5 — Lint, vet, `go test ./internal/templates/... ./internal/booklayout/...`, `make test-integration` for touched packages, web checks, e2e and `make print-check` green; result lines in the PR.

#### Test plan
Dev: requirement 3 and 4 locally; apply a few templates by hand through `book-layout/apply-template` (T-173 once merged, or by saving the page JSON through `book-layout/save` meanwhile) and look at the print route. QA: runs everything on the PR head, looks at the contact sheet and at three templates per kind on A4 with a long-name student and a student with no photo, runs the contrast and distinctness tests with a mutated template, and checks that no template contains prose or an image item.
