# E09_T-183 — Stage 2 exit check: one journey, performance budgets, parity, docs, and the report against the PRD exit criteria

**Epic:** E09-customisation-editor · **Milestone:** M4 · **Risk:** low (tests, measurements and docs; no product behaviour change except fixes of defects the check finds) · **Priority:** P2 · **Type:** test
**Depends on:** T-176, T-181, T-182 merged (T-179 too). **Read first:** PRD "Stage 2 plan" (performance budgets and exit criteria), ADR 0004 (parity method: pixel difference at 192 dpi, items within 2 px; budgets), ADR 0005, `docs/e2e.md`, `tools/e2e/` (design.spec, editor specs), `tools/print-check/` (fixtures, `fidelity.mjs`, layout cases), `docs/class-privacy-review.md`, `docs/layout-storage-budget.md`, `docs/stage2-threat-model.md`, `docs/editor-*.md`, the Postman collection `customisation-editor`.

#### Why
Stage 2 is "stable" only when the PRD exit criterion holds: a student adds, removes, moves, resizes and replaces elements on desktop and tablet, types Vietnamese correctly, undoes and redoes, and the exported PDF matches the editor in an automated parity test. We built it in 30 tasks; nobody has run it as one story with numbers against the budgets. This task does that, so the leader can close M4 on evidence.

#### Requirements (SHALL)
1. **One story spec** `tools/e2e/stage2-journey.spec.mjs` on the real stack (no mocks): a new student signs up (dev OTP shortcut as other specs do), creates a book on Memory Book, opens the editor, on the cover moves, resizes and rotates the title, adds a Vietnamese text and a sticker, uploads an own image (design image), applies a shipped template to the notes page and checks every notes page changed, saves the profile page as an own template, resets it and applies the own template back, undoes and redoes, opens History and restores an older version, presses Done, opens Print and gets the PDF, reloads and checks the layout persisted; then the same on Navy Classic; then a class admin opens the class book and sees that member's layout (and a member without layout is unchanged). Run on desktop (1280) and tablet (1024, touch) projects; the phone project runs the shorter T-181 spec.
2. **Parity**: print-check parity cases cover **every shipped template** and the story's final cover/profile/notes/back on A5, A4 and Letter (screen vs PDF raster at 192 dpi, 1-px tolerant pixel difference below 0.5%, items within 2 px: the existing ADR 0004 thresholds, report the worst numbers). Add the missing cases, do not loosen any threshold.
3. **Performance budgets, measured and reported** (numbers in the PR and in the report, method in the doc so QA reproduces it): (a) 100 items on a page, 4x CPU throttle in Chromium (CDP), drag at 30 frames/s or better (measure with `requestAnimationFrame` deltas over a scripted 2-second drag); (b) server print time of a 30-page book with layouts versus the same book without, within 10% (median of 5 runs each, same data, private stack); (c) editor route initial JS (gzip) and time to interactive on a 4x throttle; (d) `book-layout/save` p95 server time with a 128 KiB document and `template-list`, `apply-template` p95 on the private stack with 100 sequential calls; (e) memory of the editor tab after 200 nudges (heap growth under 20%, no leak of listeners: report). A failing budget is a finding with a proposed fix, not a silent change of the budget.
4. **Coverage of the API by Postman and Go tests**: a script lists every `book-layout/*` route in `api/openapi.yaml` and shows each has (a) a Postman request, (b) a rate-limit/body-cap test (T-179), (c) a class matrix cell; report gaps and close the trivial ones.
5. **Docs completeness**: `docs/` index (or README links) mentions every editor doc; `docs/e2e.md` has the commands of all new specs; the dev-shortcut register is unchanged (`docs/dev-shortcuts.md`); the privacy review table includes layouts, own templates and design images; list stale statements in docs found by grep ("phone mode is a later task", "T-xxx will") and fix them.
6. **Report** `docs/stage2-exit-report.md`: a table of each PRD exit criterion and requirement of the stage 2 outline (2a, 2b, 2c), with evidence (spec name, command, number) and a verdict (met / met with note / not met); the budgets table; open findings (from T-179, T-182 and this task) with severity; the owner manual checks still to do (macOS Telex, iOS Safari, Gboard, Firefox, VoiceOver/NVDA/TalkBack, sign-off of `docs/class-privacy-review.md` section 8) as one checklist; the Memory Book notes/back variety limit and the storage cap question (Q-065) as open decisions. No new feature work: defects the check finds are fixed here only when small (under about 30 lines); otherwise they go on the board as findings.
7. No new dependency; nothing under `.team/`.
